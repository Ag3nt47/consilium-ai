# Signal & Cross-Workstation Messaging Integration Specification

This specification documents the architecture for bridging mobile messaging apps (Signal, Bluetooth mesh, encrypted relays) into local Consilium instances across multiple workstations (macOS, Windows, Linux).

---

## 1. Core Requirements & Privacy Guardrails

1. **Zero Credential & Contact Leakage:**
   - Phone numbers, Signal registration IDs, API tokens, and local socket certificates must **never** be checked into git, logged in plain text, or included in shared transcripts.
   - All connection metadata resides in local OS keychain or `~/.config/consilium/messaging.json` (mode `0600` on Unix), protected by Consilium’s `check-secrets` pre-commit gate.
2. **Multi-Workstation Hub (Mac & Windows):**
   - When the user sends a message via Signal from their mobile device, it is dispatched to all registered, authorized workstation nodes.
   - Responses generated by the council are formatted concisely and relayed back to the mobile client.
3. **Offline / Bluetooth Fallback:**
   - When internet connectivity is unavailable, local Bluetooth Low Energy (BLE) or peer-to-peer Wi-Fi mesh relays messages between the mobile device and nearby laptops.

## 2. Architectural Components

```
                      +-----------------------------+
                      |   Mobile Device (Signal)    |
                      +--------------+--------------+
                                     |
                       (E2EE Signal / Relay or BLE)
                                     |
               +---------------------+---------------------+
               |                                           |
    +----------v----------+                     +----------v----------+
    | Workstation 1 (Mac) |                     | Workstation 2 (Win) |
    |   Consilium Core    |                     |   Consilium Core    |
    | [signal-cli daemon] |                     | [signal-cli daemon] |
    +----------+----------+                     +----------+----------+
               |                                           |
               +------------------- P2P -------------------+
                             (Sync Mesh)
```

### Component A: Signal Bridge Adapter (`signal-cli` / Socket Mode)
- **Local Daemon:** Uses a local `signal-cli` daemon running over UNIX domain socket or named pipe.
- **Message Ingestion:** Incoming messages from verified sender UUIDs are ingested as `[Human] <message>` in the active conversation turn.
- **Outbound Stream:** Council consensus summaries (or red `REQUEST:` lines) are sent back to the verified recipient.

### Component B: Cross-Instance Synchronization
- **State Relay:** Each running Consilium workstation broadcasts a cryptographic heartbeat over the local subnet (or Tailscale/WireGuard mesh).
- **Leader Election:** When multiple workstations are active, one node coordinates turns while the other maintains synchronized mirror state, preventing duplicate responses.

### Component C: Offline Bluetooth Low Energy (BLE) Peripheral
- Workstation advertises a local Consilium BLE peripheral service (`0xCONS`).
- Mobile companion app pairs via standard OS Bluetooth pairing, enabling text exchange when cellular and Wi-Fi networks are offline.
